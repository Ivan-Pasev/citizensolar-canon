# CitizenSolar Maturity Ladder RC0.1

The maturity ladder prevents public claims from exceeding implementation reality.

| Level | Label | Meaning | Public claim allowed |
|---|---|---|---|
| M0 | Concept | Doctrine, sketches, strategic frame | Conceptual only |
| M1 | Canon Draft | Public-safe written doctrine | Doctrine may be cited with boundaries |
| M2 | Architecture Draft | Blue Paper level design and schemas | Architecture-level only; no live system claim |
| M3 | Simulation | Mock data, offline models, no real dispatch | Simulation/demo only |
| M4 | Pilot Review | Site-specific review, partner handoff, readiness classification | Pilot-ready review language only |
| M5 | Supervised Pilot | Human/operator supervised deployment under known constraints | Only if real pilot exists and is documented |
| M6 | Operational Review | Audited operation under known constraints | Only with evidence and defined operating boundary |
| M7 | Certified / Regulated | External certification, approval, or regulated status exists | Only with named authority/certification/status |

## Release Rule

A downstream repo cannot claim a higher maturity level than the evidence it contains and the canon permits.

If a repo wants to advance maturity, it must add:

1. evidence;
2. boundary statement;
3. reviewer/approver note;
4. updated claim mapping;
5. updated source mapping where external facts are involved.
